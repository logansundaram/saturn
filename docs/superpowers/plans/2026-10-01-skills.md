# Skills — the user's own procedures as markdown — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user writes a procedure once as `~/.saturn/skills/<name>/SKILL.md` and runs it by typing `/<name>`. Later, Saturn can load a matching skill on its own.

**Architecture:** A pure loader, `core/skills.py`, discovers skill files in two folders: the global one (`$SATURN_HOME/skills`) and the launch folder's (`<root>/.saturn/skills`). Phase 1 is manual: a `/<name>` line becomes an ordinary turn, and the skill's body rides that turn's DYNAMIC grounding, so it costs zero extra model calls and leaves the cached prefix untouched. The same phase adds a `/skills` command, protects both folders from the file tools, and supports headless `-p "/<name>"`. Phase 2 lets the model choose: a capped `name — description` manifest in the STABLE grounding, plus a read-only `use_skill(name)` tool. It ships only if the loop benchmark shows it does not cost the catalog.

**Tech Stack:** Python 3.11+, PyYAML (already a dependency through `core/hooks.py`), LangGraph state, the Rich-based `tui.ui` helpers, pytest.

**Spec:** `docs/pivot.md` item 8 ("Skills: user-authored procedures as markdown"), `docs/research.md` Part 1 #2 and Part 2 "What the research changes in the seven plans — Skills", and the Design section below.

## Design

### The problem

Saturn can be shaped through standing instructions (`SATURN.md`), hooks and `/policy`. What it cannot hold is a *procedure*: "do my weekly review", "file this receipt", "the travel checklist". Today the user types the whole procedure every time, or puts it in `SATURN.md`, where it rides every turn's prompt whether or not it applies. `docs/dogfood.md` §13 asks for exactly this ("Create a skill called weekly-review … so I can run it every Friday"), and pivot #11 already counts `/skills` among the five commands a person needs.

The file shape has converged across agents. Claude Code's skills ([F] code.claude.com/docs/en/skills) are a folder per skill holding a `SKILL.md`: YAML frontmatter with `name` and a one-line `description`, then a markdown body. Only the descriptions sit in context; a body loads when it is used. `disable-model-invocation: true` makes a skill manual-only. Adopting that shape means users can bring skills they already have.

### Constraints that shape every choice

- **A chat question stays one model call, and the cached prefix stays byte-stable.** The prefix is `[system + tool schemas][stable grounding]` (`core/prime.py`, `tests/test_prefix_cache.py`). The catalog is already 42 tools and about 6k tokens of schema (measured 2026-10-01, `docs/research.md`). Two of the 4b's five stable loop-benchmark misses are wrong-tool picks (`chat_about_tools`, `robust_no_tool`), so another schema is a real cost, not a free one.
- **A skill is the user's instruction text, which makes the skills folders a control surface.** A planted skill would be an instruction the user never wrote: an injected web page must not be able to write one. The precedent is `hooks.yaml`, which `tools/files._control_files` refuses even when a write is approved.
- **A skill never changes the gate.** Every call a skill leads to still goes through `trust/policy.approves()`.

### Approaches considered

**A. Manual only.** `/<name>` puts the body into that turn's dynamic grounding. Zero catalog change, zero prompt change on turns that do not invoke a skill, and fully deterministic. The cost is that the model can never notice that "do my Friday thing" matches `weekly-review`.

**B. Manifest plus a `use_skill` tool, from day one.** The model sees `name — description` lines in the stable grounding and loads a body with a read-only tool call: one extra pass, and only on a matched request. It costs one schema (about 100 tokens; a draft `use_skill` schema measured 392 characters on 2026-10-02) for every user, skills or not. It also adds one more choice for a 4b that already picks the wrong tool, and its gain is unmeasured.

**C. Skills as slash commands only, with the body as a hidden user message.** The same effect as A, but it puts the body in `messages`. That puts it into history and the checkpoint, so later turns re-send it until compaction. That is strictly worse than A's per-turn grounding, which the next turn drops.

**Chosen: A now; B as a separate, measured Phase 2 in this same plan.** Phase 1 (Tasks 1–6) is everything a user needs to author and run skills, and it ships on its own. Phase 2 (Tasks 7–9) adds the manifest and `use_skill`, then runs the loop benchmark against the Phase 1 baseline with an explicit go/no-go. If the extra schema costs more than it buys, Tasks 7–8 are reverted and A stands. Model invocation is limited to GLOBAL skills that are not marked manual-only. A folder's `.saturn/skills` can arrive inside a downloaded project, so those skills run only when the user types their name.

### Decisions in detail

- **Locations.** Global: `$SATURN_HOME/skills/<name>/SKILL.md` or `$SATURN_HOME/skills/<name>.md` (`~/.saturn/skills` when unset; `config.saturn_home`). Workspace: `<workspace root>/.saturn/skills/…` (`core/workspace.root()`). A workspace skill wins over a global one of the same name, the way the workspace `SATURN.md` wins over the global one. When Saturn is launched from `~`, both resolve to the same folder and every skill is listed once.
- **The name is the file name.** It is the folder name for `SKILL.md`, otherwise the file stem, matching `^[a-z0-9][a-z0-9-]{0,63}$` (the Agent Skills naming rule). A frontmatter `name:` that disagrees is reported as a problem, and the file name still wins, because it is what the user types.
- **Frontmatter is optional.** A plain markdown file is a skill whose description is its first non-empty line, with any `#`, `-` or `*` stripped. Recognised keys: `name`, `description`, `disable-model-invocation`. Every other key (`allowed-tools`, `model`, …) is ignored, and `/skills show` names it with "a skill never changes what asks first".
- **Caps.** Body: 6,000 characters (the same as `nodes/ground._INSTRUCTIONS_CAP`), truncated with a visible note. Description: 200 characters. Phase 2 manifest: 1,500 characters, with a trailer saying how many skills did not fit.
- **Invocation.** In the REPL, a `/<name> [request]` line runs the skill when `<name>` is not Saturn's own command, alias or renamed-command pointer: built-ins always win. `/skills` lists a shadowed skill with "the built-in /<name> wins — rename the file", and so does the startup warning. The request message stays exactly as typed (`/weekly-review focus on work`), so history and the trace show what the user did. The body rides `state["skill"]`, which the ground node folds into the dynamic half. `/<name> --help` shows the skill instead of running it, matching the rule that every slash spelling accepts `--help`. Headless: `saturn -p "/weekly-review"` runs the skill the same way.
- **Discovery is read from disk each time.** There is no cache: ground already reads both `SATURN.md` files every turn, and a handful of small files costs microseconds. A skill written in the editor completes and runs without a restart.
- **`/skills` command.** Bare `/skills` lists name, description and scope, plus the two folders and any problems. `/skills show <name>` prints the path, notes and body. `/skills new <name>` writes a commented template to the global folder and prints its path; the user edits it in their editor. Every form accepts `--help`, whose details include one worked example (weekly-review).
- **Control folders.** `tools/files._refuse_control_file` grows a folder rule: a write, edit or move whose target is inside a skills folder is refused, and so is moving a folder that holds one. `run_shell` can still write there. It is gated as `destructive`, exactly like a shell write to `hooks.yaml` today; the OS-level answer is `docs/research.md` T5 (sandboxing).
- **Not a registry.** No install-from-URL, no marketplace, and nothing executed from a skill folder. One public skill registry was found holding hundreds of malicious skills, including macOS infostealers ([F] unit42.paloaltonetworks.com/openclaw-ai-supply-chain-risk/). Skills are files the user writes or copies in by hand.

### Assumptions made without asking

1. Phase 2's `skills.model_invocation` defaults to `true`, subject to the Task 9 go/no-go. If it fails, Tasks 7–8 are reverted rather than shipped switched off: a schema that is bound but disabled still costs its tokens.
2. `/skills new` writes to the global folder only. A workspace skill is created by hand. That keeps one obvious place, and the file tools refuse the workspace folder anyway.
3. Only one example ships, inside `/skills --help`. `travel-checklist` and `inbox-triage` are not shipped as templates (inbox triage is `docs/research.md` P2, which wants an awaiting-reply reader first).
4. The text after `/<name>` is the request, verbatim. There is no `$ARGUMENTS` substitution, typed parameters or `` !`cmd` `` injection (Claude Code and Goose features). See "Not in this plan".
5. `/<name>` in headless mode prints `skill: /<name>` on stderr so a script's log shows which procedure ran; stdout stays the answer.
6. Glob matching is case-sensitive: `SKILL.md` must be spelled that way. A lowercase `skill.md` is not found, which is the same rule Claude Code documents.
7. A `use_skill` call that completed is listed in the answer's Sources receipt like any read-only call. That is honest ("this answer followed your weekly-review skill"), so nothing excludes it.

### Not in this plan

- "Save what we just did as a skill", drafted by the model into a pending folder the user accepts (Hermes `skills.write_approval`, [F] hermes-agent.nousresearch.com/docs/user-guide/features/skills). This is the natural follow-up to `dogfood.md` §13, and it fits the review-queue pattern memory already uses.
- Typed parameters and a success check (Goose recipes, [F] goose-docs.ai/docs/guides/recipes/recipe-reference/).
- Skills as the prompt of a scheduled routine (`docs/research.md` P1; Claude Code's desktop scheduled tasks keep each task's prompt in a `SKILL.md`).
- `allowed-tools` / pre-approval scoped to a skill. Deliberately never: a skill does not loosen the gate.

## Global Constraints

- Tests are fully offline: no Ollama, no network, no embedder. Every test that touches configured paths uses the `isolated_paths` fixture. Every test sees an empty `$SATURN_HOME` (the autouse `_isolated_saturn_home` in `tests/conftest.py`); a test that needs skills points `SATURN_HOME` at its own `tmp_path`.
- LLM seams are monkeypatched at each node's namespace. No test reaches a model.
- `diag.log()`, never `print()`, in nodes, tools and core. Commands print through `commands._framework._print` and `tui.ui`.
- A tool that did not do its job RAISES `tools.toolspec.ToolError`; it never returns an error string.
- Every command accepts `--help` (handled by `commands._framework.dispatch`). A new command module is added to `_COMMAND_MODULES` in `commands/__init__.py` and to `_GROUPS` in `commands/system.py` (`tests/test_help.py` cross-checks it).
- `textutil.py`, `config.py` and `diag.py` stay leaves. `core/skills.py` imports only `config`, `textutil`, `core.workspace`, `diag` and `yaml`, never `commands`, `nodes` or `tools`.
- A plain chat question stays exactly ONE model call. The cached prefix `[system + tool schemas][stable grounding]` must not change from turn to turn while nothing on disk changed. Phase 1 changes neither; Phase 2 changes the catalog once (at upgrade) and the stable grounding only when a skill file changes.
- User-visible changes go under `## [Unreleased]` in `CHANGELOG.md` (Keep a Changelog).
- Commit messages follow `area: what changed` in lowercase and end with the attribution line the session's reminder specifies.
- Baseline on 2026-10-02: `.venv/bin/python -m pytest tests/ -q` → `1301 passed`.

## Review Focus

1. **A skill named like a built-in** (`/memory`, `/help`, `/privacy`): the built-in runs, nothing else changes, and `/skills` and the startup warning say the skill is shadowed. Tests: `test_a_slash_line_runs_a_skill_unless_a_builtin_owns_the_name` (Task 4) and `test_skills_lists_names_descriptions_and_shadowing` (Task 5).
2. **A broken skill file** (unclosed frontmatter, bad YAML, an upper-case file name, an empty body, a non-UTF-8 byte): named in `problems()`, never a crash, and the good skills beside it still load. Test: `test_broken_files_are_named_not_fatal` (Task 1).
3. **The model trying to plant or alter a skill**: `write_file` / `edit_file` into either skills folder, `move_file` into one, or moving the folder (or `~/.saturn`) away. All refused, even approved. Tests: `test_the_file_tools_never_write_into_a_skills_folder`, `test_the_workspace_skills_folder_is_guarded_too`, `test_moving_into_or_away_a_skills_folder_is_refused` (Task 2).
4. **Launched from `~`**, where the workspace skills folder IS the global one: each skill listed once, no duplicate-name problem. Test: `test_launched_from_home_the_two_folders_are_one` (Task 1).
5. **A skill invoked one turn must not leak into the next.** `state["skill"]` resets at the turn boundary, and the stable grounding is byte-identical with or without an invocation. Tests: `test_a_skill_never_leaks_into_the_next_turn` and `test_an_invoked_skill_rides_the_dynamic_half_only` (Task 3).

```python
"""Skills (pivot #8, plan docs/superpowers/plans/2026-10-01-skills.md): the user's own
procedures as markdown, from $SATURN_HOME/skills and the launch folder's .saturn/skills. Offline:
skills are files written into tmp_path; no model, no network."""

import pytest

from core import skills, workspace

WEEKLY = ("---\nname: weekly-review\ndescription: Friday review of the week\n---\n\n"
          "1. List what got done.\n2. List what slipped.\n")


@pytest.fixture
def home(tmp_path, monkeypatch, isolated_paths):
    h = tmp_path / "saturn_home"
    (h / "skills").mkdir(parents=True)
    monkeypatch.setenv("SATURN_HOME", str(h))
    work = tmp_path / "work"
    work.mkdir()  # set_root falls back to HOME for a folder that does not exist
    assert workspace.set_root(work) == work.resolve()
    return h


def _skill(folder, name, text, flat=False):
    path = folder / f"{name}.md" if flat else folder / name / "SKILL.md"
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(text, encoding="utf-8")
    return path


# ── the loader ───────────────────────────────────────────────────────────────────────────────


def test_no_skill_files_means_no_skills(home):
    assert skills.discover() == {} and skills.problems() == []


def test_folder_and_flat_skills_both_load(home):
    _skill(home / "skills", "weekly-review", WEEKLY)
    _skill(home / "skills", "expense", "---\ndescription: File a receipt\n---\n1. Read it.\n", flat=True)
    found = skills.discover()
    assert sorted(found) == ["expense", "weekly-review"]
    weekly = found["weekly-review"]
    assert weekly.description == "Friday review of the week"
    assert weekly.body.startswith("1. List what got done.")
    assert weekly.scope == "global" and not weekly.manual_only and weekly.extra_keys == ()
    assert found["expense"].path.name == "expense.md"


def test_frontmatter_is_optional_and_the_first_line_describes(home):
    _skill(home / "skills", "travel", "# Travel checklist\n\n- passport\n- charger\n", flat=True)
    travel = skills.get("travel")
    assert travel.description == "Travel checklist"
    assert "- passport" in travel.body


def test_a_workspace_skill_wins_over_a_global_one(home):
    _skill(home / "skills", "weekly-review", WEEKLY)
    _skill(workspace.root() / ".saturn" / "skills", "weekly-review",
           "---\ndescription: this folder's review\n---\n1. Only this project.\n")
    weekly = skills.get("weekly-review")
    assert weekly.scope == "workspace" and weekly.body == "1. Only this project."
    assert skills.problems() == []


def test_launched_from_home_the_two_folders_are_one(tmp_path, monkeypatch, isolated_paths):
    root = tmp_path / "me"
    root.mkdir()
    monkeypatch.setenv("SATURN_HOME", str(root / ".saturn"))
    workspace.set_root(root)
    _skill(root / ".saturn" / "skills", "weekly-review", WEEKLY)
    assert list(skills.discover()) == ["weekly-review"]
    assert skills.get("weekly-review").scope == "global"
    assert skills.problems() == []
    assert len(skills.control_dirs()) == 1


def test_broken_files_are_named_not_fatal(home):
    folder = home / "skills"
    _skill(folder, "weekly-review", WEEKLY)
    _skill(folder, "unclosed", "---\ndescription: never closed\n1. x\n", flat=True)
    _skill(folder, "bad-yaml", "---\nname: [unclosed\n---\n1. x\n", flat=True)
    _skill(folder, "Bad_Name", "1. x\n", flat=True)
    _skill(folder, "empty", "---\ndescription: nothing below\n---\n\n", flat=True)
    (folder / "latin1.md").write_bytes(b"---\ndescription: caf\xe9\n---\n1. x\n")
    found = skills.discover()
    assert sorted(found) == ["latin1", "weekly-review"]  # a stray byte is replaced, not fatal
    problems = "\n".join(skills.problems())
    for name in ("unclosed.md", "bad-yaml.md", "Bad_Name.md", "empty.md"):
        assert name in problems
    assert "no closing ---" in problems and "frontmatter unreadable" in problems


def test_a_name_line_that_disagrees_is_noted_and_the_file_name_wins(home):
    _skill(home / "skills", "weekly-review", "---\nname: weekly\ndescription: d\n---\n1. x\n")
    assert "weekly-review" in skills.discover()
    assert any("the file name wins" in p for p in skills.problems())


def test_a_folder_skill_beats_a_flat_file_of_the_same_name(home):
    _skill(home / "skills", "weekly-review", WEEKLY)
    _skill(home / "skills", "weekly-review", "1. the flat one\n", flat=True)
    assert skills.get("weekly-review").path.name == "SKILL.md"
    assert any("that one runs" in p for p in skills.problems())


def test_a_long_body_is_capped_with_a_note(home):
    _skill(home / "skills", "long", "1. " + "x" * (skills.BODY_CAP + 500), flat=True)
    body = skills.get("long").body
    assert len(body) < skills.BODY_CAP + 200 and "truncated" in body


def test_manual_only_and_ignored_keys_are_read(home):
    _skill(home / "skills", "private",
           "---\ndescription: d\ndisable-model-invocation: true\nallowed-tools: Bash\n---\n1. x\n")
    private = skills.get("private")
    assert private.manual_only and private.extra_keys == ("allowed-tools",)


def test_valid_names():
    assert skills.valid_name("weekly-review") and skills.valid_name("a1")
    for bad in ("", "-x", "Weekly", "a_b", "a b", "x" * 65):
        assert not skills.valid_name(bad)

def test_invocation_splits_the_name_from_the_request(home):
    _skill(home / "skills", "weekly-review", WEEKLY)
    skill, request = skills.invocation("/weekly-review focus on work")
    assert skill.name == "weekly-review" and request == "focus on work"
    assert skills.invocation("  /WEEKLY-REVIEW  ")[1] == ""
    assert skills.invocation("/weekly-review", builtin=lambda k: k == "weekly-review") is None
    assert skills.invocation("/nope") is None
    assert skills.invocation("weekly-review") is None
    assert skills.invocation("/") is None


def test_block_says_who_ran_it_and_carries_the_body(home):
    _skill(home / "skills", "weekly-review", WEEKLY)
    typed = skills.block(skills.get("weekly-review"))
    assert typed.startswith("### Skill /weekly-review — the user's own procedure: Friday review")
    assert "by typing /weekly-review" in typed and typed.endswith("2. List what slipped.")
    matched = skills.block(skills.get("weekly-review"), how="matched")
    assert "the request matches it" in matched and "by typing" not in matched
```

- [ ] **Step 3: Write `core/skills.py`**

```python
"""Skills — the user's own procedures, written as markdown (pivot #8).

A skill is a file the user writes, in the shape Claude Code and other agents share: optional
YAML frontmatter (`name`, a one-line `description`, `disable-model-invocation`) and a markdown
body of steps. Typing `/<name> [request]` runs it: the body rides that turn's DYNAMIC grounding
(nodes/ground.py), so a skill costs no extra model call and never touches the cached prefix.

Where they live — a workspace skill wins over a global one of the same name:
  $SATURN_HOME/skills/<name>/SKILL.md   or   $SATURN_HOME/skills/<name>.md   (~/.saturn/skills)
  <workspace>/.saturn/skills/<name>/SKILL.md   or   …/<name>.md

The name is the file name (the folder's, for SKILL.md): what the user types. Broken files are
named by `problems()` (the startup warning, /skills), never fatal. A skill is the user's own
instruction text, so the file tools refuse to write into these folders (tools/files
`_control_dirs`), and a skill never changes what the approval gate asks.
"""

from __future__ import annotations

import re
from dataclasses import dataclass
from pathlib import Path
from typing import Callable

from textutil import clip

SKILLS_DIR = "skills"
SKILL_FILE = "SKILL.md"
BODY_CAP = 6000          # the same budget as a SATURN.md (nodes/ground._INSTRUCTIONS_CAP)
DESCRIPTION_CAP = 200
MANIFEST_CAP = 1500      # Phase 2: the stable-grounding list of skills the model may load

_NAME = re.compile(r"^[a-z0-9][a-z0-9-]{0,63}$")
_FRONTMATTER = re.compile(r"\A---[ \t]*\n(.*?)\n---[ \t]*(?:\n|\Z)", re.DOTALL)
_KNOWN_KEYS = {"name", "description", "disable-model-invocation"}


@dataclass(frozen=True)
class Skill:
    name: str
    description: str
    body: str
    path: Path
    scope: str               # "global" ($SATURN_HOME/skills) | "workspace" (<root>/.saturn/skills)
    manual_only: bool        # disable-model-invocation: true
    extra_keys: tuple        # frontmatter keys Saturn ignores (allowed-tools, model, …)


def global_dir() -> Path:
    from config import saturn_home

    return saturn_home() / SKILLS_DIR


def workspace_dir() -> Path:
    from core import workspace

    return workspace.root() / ".saturn" / SKILLS_DIR


def _folders() -> "list[tuple[str, Path]]":
    """(scope, folder), global first. Launched from ~ the two are one folder: listed once."""
    out: list = []
    seen: set = set()
    for scope, folder in (("global", global_dir()), ("workspace", workspace_dir())):
        try:
            key = folder.resolve()
        except OSError:
            key = folder
        if key in seen:
            continue
        seen.add(key)
        out.append((scope, folder))
    return out


def control_dirs() -> "list[Path]":
    """The folders the file tools must never write into (tools/files): a skill is an instruction
    the model follows as the user's own, so a file planted there is one the user never wrote."""
    return [folder for _scope, folder in _folders()]


def valid_name(name: str) -> bool:
    return bool(_NAME.match(str(name or "")))


def _first_line(body: str) -> str:
    for line in body.splitlines():
        text = line.strip().lstrip("#").strip().lstrip("-*").strip()
        if text:
            return text
    return ""


def _parse(path: Path, scope: str) -> "tuple[Skill | None, str | None]":
    """(skill, problem) for one file; a problem with no skill means the file was skipped."""
    name = path.parent.name if path.name == SKILL_FILE else path.stem
    if not valid_name(name):
        return None, (f"{path}: {name!r} is not a skill name — lowercase letters, digits and "
                      "hyphens, up to 64 — skipped")
    try:
        # errors="replace": a hand-edited file with a stray non-UTF-8 byte still loads.
        text = path.read_text(encoding="utf-8", errors="replace").lstrip("﻿")
    except OSError as exc:
        return None, f"{path}: unreadable, skipped ({exc.strerror or exc})"
    meta: dict = {}
    body = text
    m = _FRONTMATTER.match(text)
    if m:
        try:
            import yaml

            meta = yaml.safe_load(m.group(1)) or {}
            if not isinstance(meta, dict):
                raise ValueError("expected key: value lines")
        except Exception as exc:
            return None, f"{path}: frontmatter unreadable, skipped ({' '.join(str(exc).split())})"
        body = text[m.end():]
    elif text.startswith("---"):
        return None, f"{path}: frontmatter has no closing --- line, skipped"
    body = body.strip()
    if not body:
        return None, f"{path}: no steps after the frontmatter, skipped"
    if len(body) > BODY_CAP:
        body = body[:BODY_CAP] + f"\n… ({path.name} truncated at {BODY_CAP} characters — keep a skill short)"
    problem = None
    declared = str(meta.get("name") or "").strip()
    if declared and declared != name:
        problem = f"{path}: its name: line says {declared!r}; the file name wins — type /{name}"
    description = " ".join(str(meta.get("description") or "").split()) or _first_line(body)
    extra = tuple(sorted(k for k in map(str, meta) if k not in _KNOWN_KEYS))
    return Skill(name=name, description=clip(description, DESCRIPTION_CAP), body=body, path=path,
                 scope=scope, manual_only=meta.get("disable-model-invocation") is True,
                 extra_keys=extra), problem


def _candidates(folder: Path) -> "list[Path]":
    """One folder's skill files: every <name>/SKILL.md first, then every flat <name>.md."""
    try:
        nested = sorted(p for p in folder.glob(f"*/{SKILL_FILE}") if p.is_file())
        flat = sorted(p for p in folder.glob("*.md") if p.is_file() and p.name != SKILL_FILE)
    except OSError:
        return []
    return nested + flat


def _scan() -> "tuple[dict[str, Skill], list[str]]":
    found: dict = {}
    problems: list = []
    for scope, folder in _folders():
        here: dict = {}
        for path in _candidates(folder):
            skill, problem = _parse(path, scope)
            if problem:
                problems.append(problem)
            if skill is None:
                continue
            if skill.name in here:
                problems.append(f"{path}: /{skill.name} is also {here[skill.name].path} — that one runs")
                continue
            here[skill.name] = skill
        found.update(here)  # this folder's skills replace the global ones of the same name
    return found, problems


def discover() -> "dict[str, Skill]":
    """Every loadable skill by name. Read from disk on each call (a handful of small files):
    a skill written in the editor runs without a restart."""
    return _scan()[0]


def problems() -> "list[str]":
    """What the skill files got wrong — one sentence each, naming the file."""
    return _scan()[1]


def get(name: str) -> "Skill | None":
    return discover().get(str(name or "").strip().lstrip("/").lower())


def invocation(line: str, builtin: "Callable[[str], bool]" = lambda key: False
               ) -> "tuple[Skill, str] | None":
    """(skill, request text) for a `/name …` line, or None: not a slash line, a name
    `builtin(name)` claims (Saturn's own commands always win), or no skill by that name."""
    text = str(line or "").strip()
    if not text.startswith("/"):
        return None
    parts = text[1:].split(None, 1)
    if not parts:
        return None
    key = parts[0].lower()
    if builtin(key):
        return None
    skill = discover().get(key)
    if skill is None:
        return None
    return skill, (parts[1].strip() if len(parts) > 1 else "")


_HOW = {
    "typed": ("The user ran it by typing /{name}. The text after the name in their message is "
              "what to apply it to; with nothing after it, run it as written."),
    "matched": "You loaded it because the request matches it. Apply it to the request.",
}


def block(skill: Skill, how: str = "typed") -> str:
    """The skill as a grounding block (a typed /name) or a use_skill observation (matched)."""
    return (f"### Skill /{skill.name} — the user's own procedure: {skill.description}\n"
            + _HOW[how].format(name=skill.name)
            + " Follow its steps in order; every action still asks for approval as usual.\n\n"
            + skill.body)
```

```python
"""
/skills — the user's own procedures (core/skills.py, pivot #8): list them, read one, start a new
one. Running one is typing its name — `/weekly-review` in the REPL (app/repl.py) or
`saturn -p "/weekly-review"` headless.
"""

from __future__ import annotations

from commands._framework import command, resolves, _print

TEMPLATE = """\
---
name: {name}
description: One line saying what this does and when to use it
# disable-model-invocation: true   # uncomment so only typing /{name} runs it
---

Steps Saturn follows when you type /{name}. Anything you type after the name is the request
these steps are applied to.

1. Say what to look at or gather first.
2. Say what to do with it.
3. Finish with a short summary: what was done and what is left.
"""


@command(
    "skills",
    "Your own procedures: list them, read one, or start a new one.",
    usage="/skills [show <name> | new <name>]",
    details="""
A skill is a procedure you write once in markdown and run by typing its name. Saturn follows
its steps for that request; every action it leads to still asks for approval as usual.

  /skills                 list your skills and where they live
  /skills show <name>     print one skill
  /skills new <name>      write a template to ~/.saturn/skills/<name>/SKILL.md
  /<name> [request]       run a skill ("/weekly-review focus on work")
  /<name> --help          show it instead of running it

Where they live (a folder's own skill wins over a global one of the same name):
  ~/.saturn/skills/<name>/SKILL.md  or  ~/.saturn/skills/<name>.md
  <this folder>/.saturn/skills/<name>/SKILL.md

Saturn never writes these folders itself; edit the files in your editor. A skill named like a
built-in command (/help, /memory, …) never runs — rename its file. Keys other than name,
description and disable-model-invocation (allowed-tools, …) are ignored: a skill never changes
what asks first.

Example — ~/.saturn/skills/weekly-review/SKILL.md:

  ---
  name: weekly-review
  description: Friday review — what got done, what slipped, what is next
  ---
  1. List this week's calendar events and the reminders completed or overdue.
  2. Read my note titled "This week" if there is one.
  3. Answer in three short lists: done, slipped, next week.
""",
)
def _skills(ctx, args):
    from core import skills, workspace
    from tui import ui

    sub = args[0].lower() if args else "list"
    rest = args[1:]
    if sub in ("list", "ls") and not rest:
        _list(skills, workspace, ui)
    elif sub == "show" and len(rest) == 1:
        _show(skills, workspace, rest[0])
    elif sub == "new" and len(rest) == 1:
        _new(skills, workspace, rest[0])
    else:
        _print("  usage: /skills [show <name> | new <name>] — /skills --help explains")


def _list(skills, workspace, ui) -> None:
    found = skills.discover()
    ui.section("skills", "run one by typing /<name> · /skills show <name> · /skills new <name>")
    rows = []
    for name in sorted(found):
        skill = found[name]
        notes = []
        if resolves(name):
            notes.append(f"the built-in /{name} wins — rename the file")
        if skill.manual_only:
            notes.append("only when you type it")
        text = skill.description + (f"  ({'; '.join(notes)})" if notes else "")
        rows.append(("/" + name, (text, "dim"), (skill.scope, "dim")))
    if rows:
        ui.table(rows)
    else:
        ui.note("no skills yet — /skills new <name> writes one in "
                + workspace.display(skills.global_dir()))
    _print(f"  folders: {workspace.display(skills.global_dir())} · "
           f"{workspace.display(skills.workspace_dir())} (this folder's; wins on a shared name)")
    for problem in skills.problems():
        ui.warn(problem)


def _show(skills, workspace, name: str) -> None:
    skill = skills.get(name)
    if skill is None:
        _print(f"  no skill named {name} — /skills lists them")
        return
    _print(f"  /{skill.name} · {workspace.display(skill.path)} ({skill.scope})")
    _print(f"  {skill.description}")
    if resolves(skill.name):
        _print(f"  typing /{skill.name} runs the built-in command, not this skill — rename the file")
    if skill.manual_only:
        _print("  runs only when you type its name")
    if skill.extra_keys:
        _print(f"  ignored: {', '.join(skill.extra_keys)} — a skill never changes what asks first")
    if skill.path.name == skills.SKILL_FILE:
        others = sorted(p.name for p in skill.path.parent.iterdir() if p.name != skills.SKILL_FILE)
        if others:
            _print(f"  not used: {', '.join(others)} — Saturn reads only SKILL.md and runs "
                   "nothing from this folder")
    _print("")
    for line in skill.body.splitlines():
        _print(f"    {line}" if line.strip() else "")
    _print("")


def _new(skills, workspace, name: str) -> None:
    key = name.lstrip("/").lower()
    if not skills.valid_name(name.lstrip("/")):
        _print(f"  {name}: a skill name is lowercase letters, digits and hyphens (up to 64), "
               "e.g. weekly-review")
        return
    if resolves(key):
        _print(f"  /{key} is a built-in command — pick another name")
        return
    existing = skills.get(key)
    if existing is not None:
        _print(f"  /{key} already exists: {workspace.display(existing.path)} — edit it there")
        return
    path = skills.global_dir() / key / skills.SKILL_FILE
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(TEMPLATE.format(name=key), encoding="utf-8")
    _print(f"  wrote {workspace.display(path)} — open it in your editor and replace the steps; "
           f"/{key} runs it")
```

```python
# ── Phase 2: the skills Saturn may load on its own (use_skill) ─────────────────────────────


def model_invocable() -> "list[Skill]":
    """The skills the model may load itself, sorted by name: GLOBAL ones (only the user writes
    $SATURN_HOME/skills) not marked disable-model-invocation, while skills.model_invocation is
    on. A folder's .saturn/skills came with the folder — a downloaded project could carry one —
    so those run only when the user types their name."""
    from config import get_config

    if not get_config().get("skills.model_invocation", True):
        return []
    return [s for _n, s in sorted(discover().items()) if s.scope == "global" and not s.manual_only]


def manifest() -> str:
    """The `### Skills` section of the STABLE grounding: one `- name — description` line per
    model-invocable skill, in name order, cut at MANIFEST_CAP with a trailer counting the rest.
    Byte-identical across turns while the files are unchanged (the prefix cache). "" when
    there is nothing to list."""
    listed = model_invocable()
    if not listed:
        return ""
    lines: list = []
    used = 0
    for s in listed:
        line = f"- {s.name} — {s.description}"
        if used + len(line) + 1 > MANIFEST_CAP:
            break
        lines.append(line)
        used += len(line) + 1
    left = len(listed) - len(lines)
    if left:
        lines.append(f"- … {left} more not listed (the user can run any with /<name>)")
    return ("### Skills (the user's own procedures — when a request matches one, call use_skill "
            "with its name first, then follow its steps)\n" + "\n".join(lines))
```

```python
"""
use_skill — the model loads one of the user's skills (core/skills.py, Phase 2 of
docs/superpowers/plans/2026-10-01-skills.md).

The stable grounding lists the skills it may load (`core.skills.manifest`: global, not
manual-only, skills.model_invocation on); the observation is the skill's body. Read-only and
TRUSTED: a skill is the user's own instruction text, from a folder the file tools never write.
A skill never changes the gate — every call it leads to is asked about as usual.
"""

from tools.toolspec import ToolError, register_tool


@register_tool("read_only")
def use_skill(name: str):
    """Load one of the user's own procedures by the name the grounding's Skills list shows, then
    follow its steps. Call it first when a request matches a listed skill's description. Only
    names in that list can be loaded."""
    from core import skills

    key = str(name or "").strip().lstrip("/").lower()
    allowed = {s.name for s in skills.model_invocable()}
    skill = skills.get(key) if key in allowed else None
    if skill is None:
        listed = ", ".join(sorted(allowed)) or "none"
        raise ToolError(f"No skill named {key!r} can be loaded here. Skills you may load: "
                        f"{listed}. If none fits, do the request without one.")
    return skills.block(skill, how="matched")
```

```python
class _skill_fixture:
    """Point $SATURN_HOME at a throwaway folder holding LOOP_SKILL for ONE task — the user's own
    ~/.saturn (SATURN.md, hooks, skills) is out of that one prompt and back for the rest."""

    def __enter__(self):
        import os
        import tempfile

        self._before = os.environ.get("SATURN_HOME")
        self._dir = tempfile.mkdtemp(prefix="saturn_bench_skill_")
        name, body = LOOP_SKILL
        path = Path(self._dir) / "skills" / name / "SKILL.md"
        path.parent.mkdir(parents=True)
        path.write_text(body, encoding="utf-8")
        os.environ["SATURN_HOME"] = self._dir
        return self

    def __exit__(self, *exc):
        import os
        import shutil

        if self._before is None:
            os.environ.pop("SATURN_HOME", None)
        else:
            os.environ["SATURN_HOME"] = self._before
        shutil.rmtree(self._dir, ignore_errors=True)
        return False
```
